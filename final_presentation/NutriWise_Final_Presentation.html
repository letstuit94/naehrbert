How we measure success

The hard part: cryptic receipt text → a real food

"AB Bud 6x0,3l MW"  →  ?

Every receipt line has to become a real food with real nutrients — but there was no answer key for "what food is this, really?"

So we built one: a human-checked test set of 180 real receipt lines.

Our simple test: is the correct food among the top 5 the app shows you?

Data — sources, shape & challenges

Three data worlds, stitched together

Grocery receipts
Real German receipts (Lidl / Netto / Edeka), read on the phone itself → items. Private: nothing leaves the device.
Open Food Facts
Crowd-sourced branded-product data. Backup for products the official table doesn't have.
BLS 4.0 table
German federal food database — ~7,140 foods. Our primary source of reliable nutrients.
OUR TEST SET (for matching)
45 → 180 real receipt lines · 152 unique
Earlier EDA sample: 76 items across 227 purchases.
Each line checked against all 7,140 foods.
HONEST DATA CHALLENGES
•Cryptic text, brand-vs-generic ("Budweiser" → "Pilsner Bier")
•Real receipts are harder than clean text (brand, size, "bio")
•US food database tried & rejected — blind to German foods (Quark, Schmand)

Backup — the metric in technical terms

Recall@5 on a human-verified gold set

For the technically curious — the plain-language version is on the main slides.
Gold set
180 real receipt lines (grown from 45); 152 unique. Each labeled against the full 7,140-food BLS corpus — not a shortlist, or the score would be inflated.
Metric — Recall@5
Share of lines where the correct food is in the top-5 candidates the matcher returns. Also track Top-1 (auto-pick) and lines-resolved coverage.
Label quality
Human spot-check: ~3% label-error rate on the gold labels; verdicts cross-checked.
Resolver tiers
Tier 0 learned/confirmed → Tier 1 BLS 4.0 → Tier 2 Open Food Facts fallback → left open. Embedding similarity is a tie-breaker only, not the primary matcher.
